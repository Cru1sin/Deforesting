# 缺失数据处理设计

## 目标

在 `缺失处理` 分支中，将循环结构有效性与局部数据可用性分开，避免因为一个约 3 小时循环中缺失几分钟就废弃整个循环。原始循环和原始观测永久保留；未观测点保留为 NaN；传感器插值和下游分析资格由 Pipeline 2 按变量类型、缺口范围和分析任务决定。

## 现状问题

当前 `prepare` 阶段调用 `preprocess_directory`。该函数除了读取文件、拼接分片、解析时间和做类型转换外，还包含短缺口插值入口。这样导致数据加载和缺失处理职责混在一起。

此外，准备阶段会把传感器缺口超过阈值的完整循环标记为 `contaminated`，后续基线和候选分析通过 `cycle_quality`/`cycle_gap_contaminated` 直接排除整个循环。这个粒度过粗，不能表达“某个变量的某个窗口不可用，但同一循环其他时间和变量仍可用”。

## 设计决策

### 1. Pipeline 1 只加载并保留缺失

`src/frost_analysis/data/sensors.py` 提供 `load_sensor_data(input_dir)`，负责：

- 读取监测文件；
- 拼接同一参数组的分片；
- 按时间排序并去重；
- 解析时间和可识别的数值类型；
- 外连接不同参数组，使任一参数组的时间点都得到保留；
- 输出缺失区间和数据质量摘要。

该函数不再提供或执行插值参数。`merge_parameter_fragments` 也不再执行短缺口插值；原始空值和无法解析值对应的主值列保持 NaN，已有的原始值、非法值和缺失标记继续保留为审计信息。

`prepare.py` 使用明确的变量名 `sensor_load_result`，调用：

```python
sensor_load_result = load_sensor_data(config.paths.raw_dir)
```

准备产物不对传感器数值插值。没有匹配到传感器时刻的 RGB 路径列保持 NaN；图片文件本身不做像素级插值。

### 2. Pipeline 2 承担可选的传感器缺失处理

`src/frost_analysis/processing/missing.py` 是唯一的缺失策略入口。默认策略为：

- 连续数值传感器：仅在同一 `cycle_id`、同一 `cycle_stage` 内，对有前后有效值的局部缺口做时间线性插值；缺口跨度超过配置上限时保持 NaN；
- 控制量：仅在同一循环和阶段内做限定时长的前向保持；
- 目标量 `heating_capacity`、`power_total`、`cop`、`water_heating_capacity`、`water_cop`：不插值，缺失保持 NaN；
- RGB 路径和图像元数据列：不参与数值插值，缺失保持 NaN；
- 不允许跨循环、跨阶段填充。

插值必须保留对应的 `__interpolated` 审计标记；主数据仍能通过 `__missing`、质量摘要和缺失区间定位原始缺口。将来关闭传感器线性插值时，只需在 Pipeline 2 配置中选择不插值，输入仍然是同一份 NaN 保留数据。

### 3. 循环状态与局部可用性解耦

循环的 `cycle_status` 只反映循环分段、持续时间、除霜状态和运行模式等结构性条件。传感器存在长缺口时，不再仅因为该缺口把结构有效的循环改为 `long_gap` 并从所有任务排除。循环摘要继续记录最大缺口、缺口区间、覆盖率和 RGB 完整率，供任务层选择。

对 Pipeline 2 的滑动窗口：

- 每个变量单独计算观测覆盖率和真实时间跨度；
- 窗口内部缺口过长或有效观测不足时，该变量该窗口输出 NaN/不可用标记；
- 同一循环其他窗口、其他变量和其他阶段不受连带删除；
- 窗口资格仍由现有 `minimum_coverage` 和真实时间缺口检查控制。

对循环级分析：

- 需要逐循环统计的任务只能使用其目标变量和所需窗口可用的循环；
- RGB 不完整本身不能阻止传感器循环参与传感器任务；
- 循环摘要保留传感器和 RGB 两套质量字段，任务层按需要筛选，不通过删除循环行来实现筛选。

## 数据流

```text
原始文件
  -> load_sensor_data
  -> prepared_data.parquet（原始缺失保留为 NaN）
  -> handle_missing_data（Pipeline 2 可选局部插值）
  -> 基线、真实时间窗口、特征
  -> 按变量/窗口/任务决定可用性
```

## 兼容性与范围

- `preprocess_directory` 不再作为新的 Pipeline 1 入口；调用方和测试迁移到 `load_sensor_data`。
- 现有用户可见四个顶层产物保持不变，缺失审计继续写入 `cycle_summary.csv` 和质量字段。
- 不构造覆盖整个实验的规则时间网格，不跨循环补值，不对 RGB 图片像素做插值。
- 现有 `prepare.py` 中用户未提交的注释/空白改动不属于本设计，实施时保留，不做清理式改写。

## 验收标准

1. `load_sensor_data` 的调用不接受短缺口插值参数，返回主值列中的原始缺失为 NaN。
2. `prepare.py` 使用 `sensor_load_result`，Pipeline 1 不调用插值逻辑。
3. Pipeline 2 的线性插值只发生在同循环、同阶段和配置上限内，长缺口、边界缺口、跨阶段缺口保持 NaN。
4. 控制量、目标量和 RGB 列不被错误地线性插值。
5. 结构有效但有局部缺口的循环仍出现在 `cycle_summary.csv` 和处理数据中；只有受影响的窗口/任务失去资格。
6. 新增回归测试覆盖上述行为，并通过项目现有 pytest、ruff 和 mypy 检查。
